# `tea man` policy scope

[Tea shared scope](scope.md) defines the common Tea assumptions and outcomes.

## Intent

Permit only Tea's no-argument manpage generator when it writes the generated
manpage to standard output. The policy deliberately excludes its local-output
option and every other argument form.

## Protected action and asset

The protected action is automatic authorization of the selected `tea man`
invocation. The protected asset is local filesystem state: Tea's `--out` option
generates a manpage at a supplied local path. Standard output is not treated as
a file write by this command policy; shell redirections remain independently
modeled and are prohibited for the permitted form.

## In scope

The permission policy selects only modeled invocation events whose executable
basename is exact, case-sensitive `tea`. It consumes only the exact first
argument `man`, then returns `allow` only when no arguments remain and all of
these facts hold:

- the execution target is an `external-path`;
- the invocation directly names unqualified `tea`;
- it has no leading assignments;
- it has no shell redirections; and
- no inherited Bash function named `tea` can replace the executable.

No option or operand is accepted after `man`. In particular, Tea's only manpage-output flag is `--out`/`-o`; `-o PATH`, `--out PATH`, and `--out=PATH` defer. `--output` is not a `tea man` flag and also defers.

## Required operands

None. Bare operands and unknown dash-prefixed words defer.

## Assumptions and non-goals

The policy assumes the direct external `tea man` form generates its manpage on
standard output and has no persistent Tea-side effect. It does not prove the
identity, provenance, version, or implementation of the executable selected as
`tea`, nor does it inspect the generated bytes or command exit status.

This is not a generic manpage, output-content, environment, browser, network,
or process-sandboxing policy. It does not authorize nested commands, pipelines,
command substitutions, aliases, redirection targets, or other Tea command
paths. Those effects are evaluated separately by the harness and their own
policies.

Deliberately bypassing the local-output restriction through another executable
or an unmodeled transport is outside the non-adversarial agent threat model.

## Expected outcomes

- **permit:** only direct external bare `tea man`, with no following argv,
  assignments, redirections, or inherited `tea` function, returns `allow`.
- **defer:** every non-`man` or empty Tea route defers immediately. Any `man`
  argument or flag other than the shared route values also defers, including
   `-o PATH`, `--out PATH`, and `--out=PATH`, because the option can write a local manpage.
  Path-qualified executables, assignments, redirections, unresolved targets,
  and inherited functions also defer.
- **deny:** this permission policy has no deny rule. A separate guard policy may
  deny the invocation or a shell file access, and that deny dominates this
  policy's permit.
